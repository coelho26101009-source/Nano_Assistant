# Design references

## The current direction

NANO's interface follows the design language of
[Chatbot UI](https://github.com/mckaywrigley/chatbot-ui): a sidebar with a
primary "new conversation" button, a search field, the sections and the
conversation list grouped by day; a quiet header naming the open page, with the
model selector on the right; messages as full-width rows with an avatar and a
name; a rounded composer with a solid send button; and a palette of neutral
greys. The soft blue of the NANO symbol is the only accent, spent sparingly:
focus, links, switches and checkboxes that are on, and the mark itself.

Only the patterns were taken. No code, markup, stylesheet or asset from Chatbot
UI (MIT licence, © 2024 Mckay Wrigley) is copied into this repository, so no
attribution obligation arises from it; this note records where the direction
came from.

The tokens live in `frontend/styles/globals.css`. The base values support the
optional light theme; `:root:not([data-theme="light"])` supplies dark values
before React starts and throughout a fresh session. Components reference roles
(`--surface-hover`, `--text-muted`), never literals.

## The symbol

The approved symbol is an extremely rounded, organic N: a white body lit with
soft blue. The supplied PNG has an opaque near-white background. The runtime
asset keeps its original RGB pixels and uses an alpha mask derived from the
image's blue illumination to remove the background. No vector tracing is used.

| File | Role |
| --- | --- |
| `frontend/components/NanoLogo.tsx` | displays the raster symbol, wordmark and sidebar lockup |
| `frontend/public/branding/nano-symbol-original.png` | transparent derivative of the supplied symbol, also used as the favicon |
| `frontend/public/branding/nano-wordmark-original.png` | transparent derivative of the supplied wordmark |

The near-white body and lighting therefore remain from the supplied image.

## The wordmark

The supplied lettering is used directly, with its dark background made
transparent. Light mode applies a CSS brightness filter to keep it legible.

## Still needed

Future asset work:

- **A designer-drawn vector master of the symbol**, with the dimensional white
  and blue lighting done properly as shapes and gradients rather than a blur.
  It should include a flat variant for 16–24 px.
- **A vector master of the supplied wordmark**, if one becomes available.
- **The desktop icon set.** `electron/assets/icon.ico` (16–256 px),
  `electron/assets/tray.png` and the voice overlay's
  `electron/overlay/nano-mark.png` are still built from the previous flame
  artwork. They belong to the Electron shell, not the frontend, and are
  regenerated by `scripts/build_app_icon.ps1`, which reads the flame files
  below. Both the script and the icons should move to the new symbol together.

## Previous artwork

`frontend/public/branding/` still holds the flame-era files that the icon
pipeline reads:

| File | Role |
| --- | --- |
| `nano-mark.png` | the master artwork for the flame mark (opaque, no alpha) |
| `nano-wordmark.png` | the master artwork for the previous "NANO" lettering (opaque) |
| `nano-mark-alpha.png` | derived: the mark with a real alpha channel, cropped |
| `nano-wordmark-alpha.png` | derived: the wordmark with a real alpha channel, cropped |

The interface no longer loads any of them. They stay until the icon set above
is rebuilt from the new symbol, because `scripts/derive_brand_assets.py` and
`scripts/build_app_icon.ps1` still depend on them:

```
python scripts/derive_brand_assets.py
powershell -ExecutionPolicy Bypass -File scripts/build_app_icon.ps1
```

## `nano-ui-reference.png`

The reference for the previous shell (warm near-black surfaces, dark-glass
panels, the flame red of the mark, and a top bar of sections). It is kept for
history.

It lives here and **not** in `frontend/public/`, where it was originally
dropped. Anything under `public/` is copied verbatim into `frontend/out/` by the
static export and then packaged into the installer by electron-builder, so a
1.2 MB mockup of the interface was being shipped inside the interface. It is a
reference, not a runtime asset.
